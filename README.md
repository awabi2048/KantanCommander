# KantanCommander

## 起動トリガー詳細設定の画面仕様

## 参照画面と維持する部分

- 起動方法（レッドストーン入力／タイマー／トリガー）の選択画面は、従来の子画面の配置・背景・素材・操作を維持します。
- イベント種別の選択画面も従来の2列カード、1ページ6件、ページャ、戻る位置を維持します。種別の統合により表示件数だけ7件（6件＋1件）になります。
- イベントを1回クリックすると候補を選択し、同じ候補の再クリックで「詳細設定」へ進みます。選択中は白の縁、保存済みは水色の縁で示します。

## 詳細設定

- 詳細子画面は一般コマンド設定と同じ左右分割を使います。左は「プレイヤーの絞り込み」「対象」、操作条件のあるイベントでは「どう操作したか」です。タブは通常の選択背景と幅変化だけを使い、設定済み縁は付けません。
- 右側は通常コマンドの「対象」と同じ2列カード、詳細カード、選択縁、hover、再クリック方式を使います。独立した編集・消去・視線先指定ボタンは設けません。
- 「詳細設定」の再クリック先は通常TARGET_FILTERSと同じ詳細子画面です。ゲームモードは循環選択し、名前・タグ・種類・個体IDは通常の検証仕様とDialogを項目別に使用します。ブロック対象も素材と整数座標を同じ詳細カード方式で編集します。
- 固定操作は通常画面と同じ下端配置で、「戻る」と全条件の「確定」だけを表示します。複製・削除・ページャー・無効な消去操作は追加しません。
- 右側に固定のイベント名と選択中タブの現在値を表示します。設定値や状態はボタン名へ混ぜず、詳細カードと値行へ分離します。
- 各入力は確定まで画面内の仮設定だけを更新します。「確定」で一括保存し、「戻る」ではイベント選択へ戻ります。

## 発火時の意味

- ブロック破壊・設置は別種別のままです。ボタンと感圧板は作動した時だけ起動します。レバーは変化後のオン／オフ、クリックは左右を詳細条件として照合します。
- ブロック右クリックにはAIRへの操作も含めます。このとき `event_block=AIR` です。`event_position` は視点からブロックの `interaction_range` の先端まで進んだ座標です。実際にクリックされたブロックはないため、個別ブロック座標の条件には一致しません。
- AIRの操作イベントはPaper側が初めからキャンセル状態で渡す場合があるため、AIRだけはその予測キャンセルを理由に除外しません。両手の二重発火は主手だけを採用して防ぎます。
